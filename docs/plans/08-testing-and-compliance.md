# Testing and Compliance Strategy (applies to all phases)

Goal: demonstrable conformance to ANSI/ASHRAE 135.1-2025 Clauses 4 and 5, with every
normative rule traceable to a test, without shipping copyrighted material.

## 1. Test layers

| Layer | Location | Tooling | Gate |
|---|---|---|---|
| Unit | `tests/unit/` | pytest, parametrised seed tables from `docs/spec/*` | 95 percent coverage of the module under test |
| Property-based | `tests/strategies.py`, `@given` tests next to units | hypothesis | 2000 examples per round-trip property on CI, 200 locally |
| Fixture corpus | `tests/fixtures/epics/**` plus `expected_diagnostics.json`, `expected.json` | snapshot comparison | every fixture has expectations for strict and lenient |
| Codec conformance | `tests/codecs/test_conformance.py` | parametrised over registry | all codecs |
| Validation rules | `tests/validation/` | mutation helpers | pass, fail, skipped per rule |
| Fuzz | `tests/fuzz/` | hypothesis `binary()`/`text()` plus optional `atheris` job (nightly) | never raises, bounded time |
| CLI | `tests/cli/` | subprocess | exit codes and key lines |
| Private smoke | `tests/private/` | env var `ACE_EPICS_PRIVATE_FIXTURES` | skipped in CI, documented for maintainers |
| Performance | `tests/perf/` (marked `slow`) | pytest-benchmark optional | 10k-object budget per codec |

## 2. Conformance matrix

`tests/conformance/matrix.yaml` is the single source of truth. Each entry:

```
- id: R-4.2-COMMENT
  clause: "4.2"
  rule: "Two dashes outside a string begin a comment ending at end of line"
  digest: docs/spec/01-format-and-grammar.md#2
  tests: [tests/unit/lexer/test_comments.py::test_dashes_start_comment, ...]
  status: implemented | planned | not-applicable
  mode: both | strict-only | lenient-only
```

- Phase 1 seeds it with every rule in `docs/spec/01` (one entry per 4.4 rule letter, per
  4.4.1 letter, per 4.4.2 restriction name, per 4.1 table row, per 4.2 and 4.3 sentence).
- Phase 2 and 3 add every keyword, literal, and ordering rule in `docs/spec/02` and every
  Annex §e deviation (as `lenient-only` entries with their diagnostic code).
- Phase 5 adds C5-01 to C5-20 and the structural rules.
- A test (`tests/conformance/test_matrix.py`) fails if an entry references a test id that
  does not exist, if a test marked with `@pytest.mark.conformance("R-...")` is absent from
  the matrix, or if any `implemented` entry has zero tests.
- `scripts/gen_conformance.py` renders the matrix to `docs/site/reference/conformance.md`
  with counts per clause and per status; the docs build runs it.

## 3. Synthetic fixture corpus (`tests/fixtures/epics/`)

Authored by the team, invented vendor and values, never copied from Annex A. Layout from
`docs/spec/04-annex-a-example-analysis.md` §h, each with a sibling `expected.json`
(document snapshot) and `expected_diagnostics.json` ({"lenient": [...codes], "strict":
[...codes]}):

1. `minimal.tpi`: header, signature, four general lines, every section present and empty,
   end line. Strict-clean except D5/D6 completeness decisions.
2. `full.tpi`: every section populated with standard-conforming content; at least one
   object of each of the 25 Annex object types plus five newer types (Network Port, Channel,
   Timer, Color, Audit Log) with plausible properties; includes W and C markers, per-property
   restrictions, `?` values, a Device object whose `object-list`, bit strings, and
   `protocol-revision` are internally consistent. This file is the Phase 5 "zero errors"
   baseline and the docs example.
3. `values_scalar.tpi`, `values_time.tpi`, `values_constructed.tpi`, `markers.tpi`,
   `identifier_forms.tpi`, `case_and_layout.tpi`: one notation per property as listed in
   the Annex §h items 4 to 9.
4. `lenient/`: one file per accepted deviation (Annex §e items 2 to 23 that are
   syntactic), each expected strict-reject with a specific code and lenient-accept with a
   specific warning.
5. `negative/`: one file per hard error (missing signature or end line, unknown charset
   code, wrong first three properties, unbalanced groups, unknown restriction name,
   duplicate object identifier, proprietary object with extra properties).
6. `encodings/`: `minimal` in all six charset codes, generated by a script
   (`scripts/gen_encoding_fixtures.py`) from the UTF-8 source so they never drift.
7. `consistency/`: Phase 5 mutation sources, generated from `full.tpi` by
   `tests/validation/mutate.py` at test time rather than stored, except for a handful of
   hand-written cases that need structural changes.

Fixture rules: CRLF endings enforced by `.gitattributes` (`*.tpi text eol=crlf`) and a test
that checks bytes; a fixture README explains the licensing policy and how to add a case.

## 4. Round-trip and equivalence properties

- `P1` native: `loads(dumps(loads(f))) == loads(f)` for all fixtures and generated docs.
- `P2` writer strictness: `parse(dumps(doc), strict=True)` has zero diagnostics.
- `P3` codec identity: for each codec `c`, `c.loads(c.dumps(doc)) == doc`.
- `P4` cross-codec cycle: `epics -> json -> yaml -> ttl -> epics` is identity.
- `P5` determinism: `dumps` twice is byte-identical, including RDF with `deterministic=True`.
- `P6` normalisation: documents that differ only in keyword case, `_`/`-`/space in names,
  whitespace, comments outside property lines, and section order (lenient) compare equal.
- `P7` value render: `parse_value(render(v)) == v` for generated value trees.
- `P8` never-raise: lexer, value parser, reader, and every codec reader return diagnostics
  instead of raising for arbitrary bytes (hypothesis `binary()` and mutated fixtures).

## 5. Validation rule testing

For each rule: a passing case from `full.tpi`, at least one failing mutation, a skipped
case with `NullProvider` where the rule needs knowledge, and a `caused_by` case where a
dependency rule already failed. The 32 seeds in `docs/spec/03` §7 are the minimum set.
Knowledge data files have their own structural tests (uniqueness, revision monotonicity,
cross-references resolve) and a dev-only cross-check against bacpypes3 enumerations.

## 6. Private Annex A smoke test

Maintainers who hold a licensed copy may run `tests/private/test_annex_a.py` with
`ACE_EPICS_PRIVATE_FIXTURES=/path/to/private/dir`. It asserts: lenient parse succeeds; 25
objects; the Annex §e deviation codes appear; Phase 5 reports C5-07 and C5-08 failures
(Annex A is known to violate them). It is documented as optional and never run in CI.

## 7. CI gates summary

- ruff, ruff format, pyrefly: blocking.
- pytest with coverage: 90 percent overall, 95 percent for `lexer`, `values`, `model`,
  `codecs`, `validation`.
- Conformance matrix integrity test: blocking.
- Codec conformance suite on ubuntu and windows: blocking.
- Docs strict build and generated pages up to date (`git diff --exit-code` after
  generation scripts): blocking.
- Nightly: fuzz job (longer hypothesis budgets, atheris if enabled), performance budget.
